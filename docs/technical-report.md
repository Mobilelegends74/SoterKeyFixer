# TEST 6 — полный цикл вместо быстрого restart

## Что подтвердил архив (6)

TEST 5 на boot ID 1a41fd96-49b3-428d-9dfa-3c198bec219b выполнил автоматический
ctl.restart на uptime 71: PID 3601 → 15643. По сообщению пользователя ключ
оставался FAIL. Ручной ctl.restart на uptime 116 сменил PID 15643 → 22298,
после чего пользователь получил PASS. Команда в обоих случаях была одинаковой.
Это исключает отсутствие автоматического запроса, но не устанавливает, почему
поздний запрос дал другой результат. Записи running не проверяют ключ.

Исходная 1.3 использовала stop → пауза 2/3 секунды → очистка APK → start,
причём при загрузке повторяла это 25 раз после задержки 90 секунд.
TEST 1–5 заменили последовательность на ctl.restart и добавили условия, которые
оказались излишними для исходной задачи. TEST 1 ошибочно блокировал восстановление
по неуспешному Binder-запросу пакета; TEST 4 блокировал Action grace/cooldown.
Эти ошибки исправлены в предыдущих коммитах, но автоматический FAIL оставался.

## Реализация TEST 6

Один полный цикл после boot-completed; Action использует тот же backend:

1. Сериализовать запрос через repair.lock; проверить включение модуля, завершение
   загрузки, отсутствие shutdown, известное состояние vendor.soter и общий бюджет.
2. Послать ctl.stop vendor.soter и подтвердить stopped (до 10 опросов по секунде).
3. Выдержать 3 секунды в остановленном состоянии, затем ctl.start vendor.soter.
4. Наблюдать возврат running/смену PID; результат ключа остаётся UNKNOWN_UNVERIFIED.

Это возвращает существенное отличие от 1.3 — окно остановленного сервиса,
вместо серии быстрых restart. Гипотеза о необходимости такого окна пока не
подтверждена на устройстве. Заявления о сбросе/восстановлении TEE-ключей нет.

Очистка данных, создание ключей и 25 повторов не возвращены: TEST 2/5 показали
пользовательский PASS после ручного запроса без очистки. Фильтры manufacturer,
SDK, device, SDK APK, CE unlock, готовности keystore/qsee и init-профиля удалены.
Init-профиль и сведения APK остаются исключительно диагностическими.

Бюджет максимум 3 запроса за загрузку сохранён. Один boot-запрос, ручной cooldown
15 секунд, отмена по pause/disable/update/remove, locks и ограниченные логи.
Поздний подтверждённый stopped допускает автостарт с cooldown 300/900 секунд.
Периодического restart работающей службы и удержания wakelock нет.

При неудачной остановке/прерывании cleanup пробует вернуть службу через start.
SIGKILL и падение системы не перехватываются; это ограничение схемы stop/start.
Другие TEE/Keystore/RKP/StrongBox службы не останавливаются и их данные не читаются.

## Проверка и границы результата

Тесты пересмотрены под новый контракт полного цикла. Проверяются обе точки
запуска, остановка до паузы, ровно один цикл, возврат start при ошибке, конкуренция,
отмена, независимость от device/SDK/APK/unlock, бюджет, cooldown и readonly-диагностика.
Три shell: dash, BusyBox ash, mksh. ShellCheck, состав ZIP, версия 1.4-test6/code19,
воспроизводимость. Artifact GitHub сам является установочным ZIP без вложенного ZIP.

На телефоне: перезагрузка, затем заводской тест без Action; отдельно проверка
обычной SOTER-аутентификации и ранее работавших RKP/StrongBox/аттестации.
До этого автоматическое получение PASS в TEST 6 не считается подтверждённым.
Проверенного функционального OEM-пробника нет: поздний FAIL при running
не распознаётся автоматически. Нельзя гарантировать устранение такой ошибки
по одному лишь состоянию процесса или успешной сборке.
