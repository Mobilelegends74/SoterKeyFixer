# Soter Key Fixer 1.4 — TEST 6

Один полный цикл восстановления `vendor.soter` после загрузки Android:
**остановка → подтверждение остановки → пауза 3 секунды → запуск**.
Ручной Action выполняет тот же цикл. Нет 25 повторов, очистки данных,
привязок к модели телефона, SDK, Tencent APK или состоянию разблокировки.

Из исходной 1.3 возвращена последовательность stop/pause/start вместо быстрого
`ctl.restart`. Удалены цикл из 25 повторов и очистка Tencent APK. Это новая
тестовая реализация; работоспособность аппаратного ключа проверяется на телефоне.

## Установка

Скачайте artifact **SoterKeyFixer-1.4-TEST6** из успешного
[Actions](https://github.com/Mobilelegends74/SoterKeyFixer/actions).
ZIP устанавливается **напрямую, без распаковки** в KernelSU Next. После обновления
перезагрузите телефон, затем проверьте EngineerMode без нажатия Action.
ID `SoterFix` сохранён, versionCode 19.

Запуск происходит после `sys.boot_completed=1`; отдельного минутного таймера нет.
Подтверждение остановки ожидается до 10 секунд, сама пауза — 3 секунды.
Не проводите SOTER-аутентификацию/платежи одновременно с восстановлением.

## Ограничения и диагностика

`running` и смена PID **не доказывают исправность ключа**. Модуль не имеет
проверенного OEM-пробника, автоматически распознающего FAIL при работающей службе.
Он не генерирует ключи и не изменяет Keybox/RKP/StrongBox/KeyMint. Управляется
только буквальная служба `vendor.soter`; остальные состояния читаются для отчёта.

Сохранены блокировки от одновременного выполнения, отключение через менеджер,
общий предел 3 запросов за загрузку и 15 секунд между ручными запросами.
Автоматически выполняется один загрузочный цикл; новый процесс или Action не
обнуляют бюджет. Подтверждённая остановка службы позднее допускает ограниченный
автостарт. Повторяющегося таймера перезапуска работающей службы нет.

Если stop не подтверждён или цикл прерван обрабатываемым сигналом, cleanup
пытается запустить SOTER обратно. При SIGKILL/гибели системы shell не может
гарантировать исполнение cleanup. Неизвестное состояние службы не вызывает stop.

```sh
su -c 'sh /data/adb/modules/SoterFix/soterctl.sh status'
su -c 'sh /data/adb/modules/SoterFix/soterctl.sh diagnose'
```

Архив: `/data/adb/soterfix/soterfix-diagnostics.tar.gz`, доступ через root.
Action также сохраняет диагностику. Внутри — версия, boot ID, журнал, PID,
состояние worker, init-профиль и ограниченные SOTER-сообщения. Профиль и сведения
Tencent APK только диагностические, не блокируют запуск. Нет полного logcat или
файлов ключей; просмотрите архив перед передачей. Журнал ограничен по размеру.

Команды `pause`/`resume` приостанавливают/возобновляют модуль;
`boot-off`/`boot-on` отключают/включают загрузочный цикл (включение со следующей
перезагрузки). Бюджет при этом не сбрасывается. Диагностика остаётся после удаления.

## Проверки

ShellCheck, синтаксис и тесты в dash, BusyBox ash, Android mksh: полный цикл,
однократный boot-запуск, отсутствие фильтров по устройству/APK/разблокировке,
конкуренция, отмена, cooldown, общий бюджет, отказ остановки, cleanup и диагностика.
ZIP проверяется по составу/версии/правам и собирается воспроизводимо.
CI публикует только artifacts, без Release/тегов. Успешный CI не доказывает PASS.
